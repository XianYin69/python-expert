# 审查约束

## 取证完整性

1. 任何数字（耗时、覆盖率、行数、命中数）必须来自 `scripts/` 输出或用户提供的原文，禁止估算。
2. 脚本一律只读；需要写盘的动作必须调用方显式授权并先 `--dry-run` 预览。
3. 脚本失败/工具缺失 → `process_chain.py interrupt`，禁止跳过继续给结论。
4. 同一结论至少两条独立证据（静态扫描 + 运行输出，或两个工具交叉）。

## 九项自审（交付前逐项过）

1. 分类正确：主方向与次方向与 `classify_topic.py` 输出一致。
2. 证据可追溯：每条判断有出处路径或诊断行。
3. 判据非偏好：阻塞项来自 PEP/官方文档/实测。
4. 建议可执行：每条含改法、验证命令、回滚方式。
5. 边界声明：版本/平台/规模失效条件写明。
6. 无伪造：未运行的不写「已验证」。
7. 无越权：未修改任何既有技能目录或用户文件。
8. 链接闭合：`check-links.py` 悬空链接为 0。
9. 精简：交付长度与调用方需求匹配（SMS 短、编码技能全）。

## 违反后果

结论不可信、调用方按错误建议改动代码、评审失去复核能力。
